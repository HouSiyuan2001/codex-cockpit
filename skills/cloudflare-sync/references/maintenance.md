# 管理员维护与事故处理

只用于你自己的 Worker/D1 和已确认的空间。操作前确认账号、环境、空间 ID、设备 ID、影响和本机备份；不要输出 token_hash、真实快照或数据库全量内容。AI 读取本指南不等于获得执行删除/恢复的许可。

## 设备丢失或退出团队

owner 在桌面“设置 → 云同步 → 设备访问权限”选择对应设备，确认停用。服务器将成员标记为 revoked，后续上传/读取返回无权限；其他空间不受影响。owner 不能在这个入口停用自身。验证应使用被停用设备实际尝试访问，不能以列表消失代替验证。

这是撤销权限，不是删除：D1 保留快照供管理员恢复，其他设备的缓存和已有备份不会自动清除。泄漏的 owner 凭据需要管理员直接通过自己的 D1 控制台撤销相应成员并撤销未使用邀请，不能靠关闭建站密钥解决。

停用后不能直接重复邀请同一设备 ID：数据库保留唯一身份记录。恢复时先确认原使用者，要求其在本机删除该服务/设备对应的旧凭据（由用户处理系统授权），再由管理员在同一数据库中清除该 revoked 成员的快照、相关邀请和成员记录，最后通过新邀请沿用原设备 ID 接入。先备份，不复制或重新启用已泄漏 token。

## 删除数据

目前没有完整自助删除界面。管理员在 D1 控制台只操作已确认的目标，不运行没有 WHERE 条件的删除：

- 按 space_id 和 device_id 删除目标设备的 snapshots；先停用访问，避免重新上传。
- 按 space_id 和 device_id 核对并处理 members。members 删除可能需要先清理相关 invites 外键。
- daily_plans 是空间共享记录；个人数据还可能存在其 JSON 和 spaces 的共享配置中，需要按实际 personId 审查，不能删除整组来代替删个人。
- 删除整个空间之前，按外键依赖先处理 daily_plans、snapshots、invites、members，最后 spaces；这是不可逆操作，另行取得明确授权。
- 为团队约定备份保留期，并安排各设备清理相应缓存。云端删除不能保证撤回对方已保存的数据。

不要把数据库导出、建站密钥或 Cloudflare API token 发到聊天/Issue。D1 备份与恢复工具以[官方文档](https://developers.cloudflare.com/d1/reference/time-travel/)为准；恢复前明确可能恢复已删除数据和旧权限。

## 升级这个安全修复版本的 Worker

1. 备份并检查迁移状态。新的 schema 会拒绝未知嵌套字段，也不会向成员返回不符合 schema 的旧快照（保留数据库原记录供管理员检查，不自动删除）。先升级旧客户端，只有经过审查的聚合字段才能进入快照。
2. 将 wrangler.example.toml 的 AUTH_RATE_LIMITER 和 API_RATE_LIMITER 两段合并到自己的 ignored 配置。namespace_id 是管理员自己选择的账户内唯一整数，不是数据库 ID 或密钥；不要覆盖原 DB 配置。
3. 新 Worker 缺少任一限流绑定时返回 503，不静默失去保护。health 仍可返回正常，必须另验实际邀请/登录/同步。
4. 用自己的合成测试设备核验 429 与 Retry-After、权限隔离、快照校验和停用，再让两台真实客户端做双向验证。新源码不会自动升级任何现有服务器。

当前配置约每个边缘位置/IP 120 次请求每分钟，已认证成员另有每分钟 120 次限制。共享出口可能触发 IP 限制，管理员可按团队实际情况调整。Cloudflare 限流计数是区域性的近似计数，不是全局费用上限或 DDoS 保证；监控资源额度与 429/503，必要时配合边缘防护。[官方限流说明](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)

## 发布不等于托管公共服务

公开源码、发布安装包、部署某团队的服务器是独立动作。管理员承担自己的 Cloudflare 账户资源和费用，普通成员只接受邀请。不要开公共注册，不内置作者私有 endpoint，不配置旧 Git 自动上传。
