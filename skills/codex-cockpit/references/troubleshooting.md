# 按现象排障

## 先取最少证据

确认 App 版本、系统/架构、复现步骤、期望与实际结果。优先看控制中心中选中的成员、时间段、Token/成本和分组，以及最近采集/上传/拉取时间、脱敏错误。只在相关问题需要时读取本地文件。

“官方剩余额度”“本地 Token 历史”“按价格估算的金额”不是同一份数据。先确定坏的是哪条链路，避免用其中一个数字证明其他数字正确。

| 现象 | 先检查 | 下一步与验证 |
| --- | --- | --- |
| 额度未登录/失效 | 本机 Codex 是否正常登录；驾驶舱与 Codex 是否使用同一用户/配置来源 | 让用户在 Codex 正常重新登录后刷新驾驶舱；不要读取/粘贴 token。用量历史存在不代表额度接口登录有效 |
| Token 有，金额没有 | 成本模式、时间范围、缺价/部分数据标记、原始模型名称、价格表来源 | 新版有内置参考价格，不要求配置云同步或安装 Tokei。看“统计说明”区分缺价和缺单次用量；旧包可能缺内置模型。查看目标 checkout 的 `docs/LOCAL-PRICING.md`，用合成例子复算；未知金额不能填零 |
| 模型都变成一个大类 | App 版本、事件的模型 ID、别名归一化 | 查地图中的采集/定价模块；测试完整名称、别名与未知名称。新价格要核对官方来源，不根据名称猜价格 |
| 对方用量迟迟不变 | 两台电脑是否都在线、是否同一服务/空间、是否自动同步；分别查看采集、上传、拉取时间 | 用户已请求修复同步时，在确认空间后做一次立即同步。A 上传成功，再验证 B 拉取到同一日期的新值。健康接口成功只代表服务可达 |
| 改成员后另一台没变 | 是否同一空间、是否保存成功、共享 revision、对方最近拉取 | CAS 冲突先刷新并重新应用自己的改动，不能强制覆盖；A 改 B 收到、B 改 A 收到才算双向验证 |
| 所有用量都算给一个人 | 设备归属、是否重复使用设备标识、界面默认查看对象 | “默认查看谁”只是界面默认筛选。一台设备归一个成员；同一人多台设备可以同名归属。不要把所有设备改成同一个 ID |
| 看不到对方任务 | 来源设备的任务共享选择、最近上传、日期与成员筛选、是否收到任务明细 | 新连接默认开启，旧配置或主动关闭仍会保留；先说明共享内容，不擅自打开其他设备。缺少明细不代表零用量；“跨设备任务提示”可展开检查状态 |
| 日历/曲线日期不对 | 日/周/月粒度、当前窗口、已选日期、系统时区，以及数据来源 | 项目存在自然日与使用日等不同口径；查地图对应函数和时间戳，不批量改历史日期。跨时区用合成边界案例复现 |
| 手动计划或舒适度串人 | 选中的成员、独立手动覆盖、共享日期/版本、拟合样本归属 | 本人的手调不应挤掉别人的原分配。分别验证两个人的设置；不能把全组舒适样本当作个人样本 |
| 日历遮挡、浅色不可读、曲线断线 | 系统/主题、窗口尺寸、空值/部分数据状态 | 用合成数据复现并检查真实桌面；缺记录不补成零来连线，浏览器正常不代表透明原生窗口正常 |
| 小票 PNG 复制失败/字体异常 | 已选任务、打印/撕取阶段、字体是否加载、系统剪贴板报错 | 用虚构标题/金额，复制后粘贴到本机图片应用检查。小票可能含任务名称，不自动上传用户的小票 |

## 同步进一步定位

默认采集上传约 5 分钟，接收检查约 1 分钟，实际以该版本配置和运行状态为准；睡眠、离线和采集耗时会延迟。相关逻辑在 `src-tauri/src/usage_sync.rs`，不承诺实时。

查看配置/状态时仅提取需要的字段，不打印整个 `cloud-sync.json` 或快照。邀请失效让空间管理者通过正常入口重新邀请；不要复制另一台机器的凭据、盲目创建新空间或循环重试无效密钥。涉及服务部署、D1 迁移或 owner 价格表管理时，定位同一 checkout 的 `skills/cloudflare-sync/SKILL.md`；单独安装的 Skill 不自带服务器源码。

## 源码排查和修复

读取[仓库地图](repository-map.md)定位最小相关模块及测试。在对应 App 标签/commit 下重现，不能只用最新 main 解释旧包。只要求诊断时给证据与建议，不动代码；要求修复时保留无关更改，用虚构成员、设备、任务和模型事件添加回归测试。

先跑目标测试，再按改动风险执行开发 SOP；涉及权限、同步或定价时不能只验 UI。修复后的源码、构建出的包、实际运行版本分别确认。不能直接替换已发布资产或向用户服务器部署未经确认的修复。

## 需要反馈给维护者时

在本地准备最小复现：版本/平台、操作步骤、预期/实际、已做检查、脱敏错误、合成复现数据。截图先遮住姓名、机器名、任务标题和账号信息。先给用户审阅，用户要求提交后才发 Issue；密码/邀请码/完整 session、数据库、Keychain 内容永不作为附件。

如果权限、另一台机器或某个界面无法访问，明确剩余检查，不把“没有继续报错”当作验收通过。
