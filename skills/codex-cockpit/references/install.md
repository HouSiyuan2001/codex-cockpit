# 安装与更新

## 选对来源和文件

1. 确认系统与 CPU 架构、已有版本/安装位置、用户要首次安装还是更新。不要退出正在使用的 App，除非安装这一步需要并已说明。
2. 打开用户确认的仓库 [Releases](https://github.com/HouSiyuan2001/codex-cockpit/releases)，读取目标版本的说明与资产列表。当前包含预发布版，不能只用 `/releases/latest` 判断有没有包。不要把 `main` 的最新提交当成安装包对应源码。
3. 下载同一版本的安装包和 `SHA256SUMS`（beta.2 为 `SHA256SUMS.txt`），核对实际文件名及摘要。历史版本没有这份文件时读取该版说明，不猜校验值。macOS 通用 DMG 支持 Apple Silicon / Intel；Windows 当前是 x64 EXE，不能称为原生 ARM64 包。没有合适包时说明限制。
4. 若仓库私有，浏览器/GitHub 工具必须已有用户自己的访问权限。404 不一定是仓库不存在；没有授权就停在访问这一步，不从非官方镜像找包。

Mac 可以在仅含本次下载文件的目录使用 `shasum -a 256 "实际文件名.dmg"`；Windows 用 `Get-FileHash -Algorithm SHA256 -LiteralPath "实际文件名.exe"`。与同一 Release 的摘要逐项比较。校验表可能含另一平台文件，不要求为了校验把两个包都下载。

校验和检查的是文件一致性，不证明作者身份或没有漏洞。当前测试版 Mac 未公证、Windows 无发布者签名；以后每个版本重新读取说明，不永久假定所有版本都未签名。

## 安装和首开

- **Mac：** 打开已核对的 DMG，把 `Codex Cockpit.app` 放入用户选择的 Applications 目录，再从安装位置启动。更新前确认旧包位置，保留可恢复的旧版本，不让旧/新进程同时运行。不要从 DMG 一直运行测试后声称已安装。
- **Windows：** 启动已核对的 `x64-setup.exe`，使用用户选择的安装位置；系统提权/身份确认交给用户。不要因为下载了 EXE 就报告完成。
- **系统阻止启动：** 记录准确提示与来源。区分未知开发者提示、签名损坏、恶意软件告警。不要自动去除 quarantine、关闭 Gatekeeper/SmartScreen/Defender、添加安全排除或删除系统凭据。哈希不符或安全告警未解决时停止运行该文件。
- **没有窗口：** 这是悬浮/托盘工具，不一定有 Dock 或任务栏图标。先看悬浮窗、菜单栏/托盘与进程；再从已安装位置打开它。先排除单实例和窗口位置问题，不直接删除设置。

额度读取依赖本机可用的 Codex 登录状态。请用户在自己的 Codex 中正常登录；不要让用户发送登录文件或把别人的账号配置复制过来。登录方式/错误随 Codex 版本可能变化，必要时查官方说明。

首开确认：安装位置与版本正确 → 悬浮窗/控制中心能打开 → 本机统计状态可解释（包括尚无历史）→ 关闭再打开不丢设置。用户用到的日历、PNG 复制等功能单独验证。没有历史不应伪造数据“补齐”。

## 更新和回退

先检查安装版本是否有「设置 → 检查更新」。新版从同一仓库的正式版/测试版清单下载，验证签名后由用户确认重启安装；旧 beta.2 需先手动安装一次。仓库私有时 App 无法匿名读取清单，使用已授权的浏览器手动下载，不将 GitHub Token 放进 App。来源错误不等于已是最新版，签名失败不绕过。维护配置见仓库 `docs/AUTO-UPDATE.md`。

按目标 Release 的迁移/兼容性说明操作；普通更新不清空配置。先识别实际应用配置目录，再在本机保留必要备份，备份不入 Git、不上传。

旧版不能保证读取新版数据。回退前保留新状态，确认旧版兼容性，不能用“覆盖回去应该没事”代替检查。安装不附带云部署，也不会把所有设备自动升级。

## 没有可用安装包时

源码构建是备选，不要求普通用户先装 Rust。只有用户选择自编译或需要验证修复时，才定位 checkout，读取 `AGENTS.md`、`docs/DESKTOP-DEVELOPMENT-SOP.md`、`docs/RELEASING.md`。按其中依赖和命令构建本机平台，不在 Mac 上承诺直接产出 Windows 安装包。
