# 跨设备同步契约 v2

## 目标与边界

同步成功不再只表示文件上传成功：设备还需要接收到共享配置、采用同一计价规则，并报告配置版本。成本是模型单价下的估算，不是会员账单；未知模型、缺少事件上下文时仍保持未知，不能通过猜单价补全。

## 数据所有权与功能依赖

| 数据 | 所有者与传输 | 使用它的功能 |
| --- | --- | --- |
| 价格表、模型别名、计价策略 | 空间所有者发布版本，所有设备拉取 | 本机任务成本、个人成本分布、按成本分配额度 |
| 组员 ID、名字、设备归属 | 所有者维护，版本化配置 | 用户圆环、个人体验归属、跨设备合计 |
| 每设备按日/模型聚合用量 | 设备绑定身份上传，不交换原始会话 | Token、成本、今日与历史用量 |
| 已归属个人的体验记录 | 保留现有有界记录合并与编辑时间规则 | 体验日历、个人曲线拟合 |
| 应用版本、协议版本、采用的配置版本 | 每设备上传报告 | 发现旧版设备、配置落后与成本覆盖不完整 |
| 官方账号凭据、原始对话、项目路径 | 仅留本机，禁止共享 | 官方额度读取与本机任务细节 |
| 窗口位置、主题、语言、提醒、个人配色 | 仅留本机，不整体覆盖偏好 | 本机显示与交互 |

官方 5 小时/周额度、重置时间来自当前设备登录账号，不能拿其他账号的快照覆盖。个人上限、手动风险调整保留本机控制语义。不同设备的视觉偏好可以不同，不影响用量汇总。

## 同步顺序

1. 独立下载其他设备快照，保留最后可用缓存。
2. 拉取共享配置；所有者如有本地价格/组员修改，按预期 revision 提交。版本冲突报错，不能静默覆盖。
3. 校验共享价格、别名、组员结构。共享价格存入独立 `cloud-pricing.json`，不覆盖原始本机价格文件；共享计价时不再叠加其他设备自己的 Tokei override。
4. 价格文件仅在内容变化时更新，触发本地采集器重扫。先完成可获得的部分，不把旧快照 Token 直接乘单价。
5. 上传有界聚合快照与协议/配置版本报告。用相同设备 ID 续传，重复快照不得累加，较旧快照不得覆盖新数据。
6. 下载与上传时间分别展示；每分钟接收、每五分钟采集上传。网络故障、采集超时和休眠会延后同步。

## 成本修复

成员乙旧设备发送的 `cost: null` 保留为未知。升级后先接收共享价格，再从原始事件重扫。日总成本不完整时，仍允许已可估算的模型金额更新，不能要求整天的所有模型都可计价才发布已知部分。

同 Token 数的重扫只替换对应模型金额，不增加 Token。历史缓存中已知金额不因不完整重扫被清空；保留历史天数会继续通过快照的 retainedDays 报告。不能把共享配置版本一致解读为历史所有费用已经重算完成。

## 兼容与失败

- `/v1` 快照接口继续兼容旧设备。共享 v2 配置建立后，旧版所有者的 groupSettings 不再覆盖新版配置。
- 未报告 v2 能力的设备显示“旧版协议，需升级以接收统一价格表”。
- 配置版本不一致显示待更新；成本按今日可估算模型数显示覆盖情况，不把缺失当成零成本。
- 无网络时读取缓存；新成员尚无价格配置时不宣称计价就绪。
- 采集和可选项目元数据识别均有隔离/超时保护，不能拖住云端接收。

## 验收要求

主机发布配置、另一台新设备下载同版配置并重扫、已知模型金额出现、重复同步不翻倍、旧设备不覆盖新版配置、错误配置不覆盖有效价格、无原始对话/凭据进入共享配置。各设备实际安装和重扫必须逐台核实，不能由主机测试代替。

当前日账本继承设备日历时区，异地设备应使用一致的日历时区；跨时区历史重分桶尚未实现。历史事件已经缺失的设备无法仅靠聚合 Token 恢复精确上下文计价。
